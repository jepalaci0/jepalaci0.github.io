Professional Self-Assessment

During my time in the Computer Science program at Southern New Hampshire University, I feel as if I developed a better understanding of how different areas of technology work together. When I started, I was mostly interested in writing code and better understanding how computer systems operate. As I worked through more advanced courses, I began to see how broad the field really is and how areas like software development, databases, security, and troubleshooting all connect. My experience in customer account support at Walmart has also influenced how I approach technical problems. Much of my work involves identifying issues, researching their causes, and finding solutions while communicating with the people affected. My goal after graduation is to continue developing my career in IT and technical support, using my programming experience to better understand and troubleshoot the systems I work with.

Communication and collaboration have been important parts of my development, both academically and professionally. My current job has taught me how important it is to explain complicated information clearly, whether I am speaking with a customer or working with another team. One area I particularly enjoyed studying was Agile software development, which helped me understand how planning, communication, and feedback contribute to a successful project. I learned how development teams organize responsibilities and adjust their work as a project progresses. I can relate these methods to my professional experience because fixing a problem often involves communicating with different people who may each understand a different part of the issue.

As I moved into the more advanced classes, I started to realize that getting a program to work was only part of the assignment. Sometimes taking the time to organize the code and understand how everything connects is just as important. I spent plenty of time figuring out why something wasn't working, making changes, and then realizing I had created an entirely different problem in the process. One example was Travlr, a travel website I developed for a class project. The application included a public website for viewing travel packages and a separate area for managing the information displayed. Since these parts depended on each other, a problem in one area could affect something completely different. There were times I spent too long trying to fix what was visible on the screen before realizing the actual problem was happening somewhere else. That experience reminded me of troubleshooting at work and helped me understand why the way information is organized and processed matters just as much as the final result.

Security was another area I became more familiar with as I worked through the program. In that same travel website project, I worked on the login system and controlling which parts of the application users could access. Visitors could view the available travel packages, but only authorized users were supposed to make changes to those listings. This helped me understand that building a functioning application also means considering what users should and should not be allowed to do. In my current role at Walmart, protecting customer information and verifying account access are already important parts of my job. Working on the development side helped me see more of what goes into those protections behind the scenes and how overlooking security during development could create problems later.

For my final portfolio, I decided to return to two projects I had completed earlier in the program and improve them in three different areas. The first was PitchEvent, an Android application designed for creating and managing events. I improved how events were created, edited, and updated, along with how their information was stored. The second was the Grazioso Salvare Rescue Dashboard, an application that used animal shelter records to identify possible rescue animals. Originally, the dashboard used basic requirements to filter animals, so I changed that process to assign scores and rank candidates based on how well they matched those requirements. I then returned to the same project for my database enhancement, improving how users could search through the shelter records. What I liked about these enhancements was being able to look at something I had already finished and find ways to make it better. I wasn't starting from nothing, and I could see how much more I understood compared to when I first completed those assignments.

Looking back at the program, I think one of the biggest things I've gained is a better understanding of how much goes into the technology people use every day. I still enjoy programming, especially when I finally get something working after spending time troubleshooting it, but my main interest is in IT and technical support. My experience at Walmart has already given me a foundation in problem-solving and communicating with customers, and my degree has helped me understand more of the technical side of those problems. I know there is still plenty for me to learn, but I feel better prepared to take on more technical responsibilities and continue building my career in this field.

Enhancement One

Software Design & Engineering

PitchEvent Android Application

The artifact I selected for this enhancement is an Android application I originally created in CS 360 called PitchEvent. The application allows users to create an account, log in, and create and manage events in a pickup-sports-centered system that can be adapted for other types of events.

I selected this artifact because it demonstrates my specific experience with Java coding, Android applications, and introductory SQLite database operations. The connectivity between all parts of the application was the main focus of the original project, showing that I know how to create a functioning multi-tiered system.

Enhancement Narrative

For my enhancement, I focused on improving how events are created and edited. As I outlined in my code review, I added an improved event lifecycle that allows events to move through status updates such as Upcoming, Reminder Due, Completed, and Archived. The status is stored in SQLite so it remains after restarting the application or logging out.

I also improved my original event model. Before, I had the date and time stored together, along with the location and notes as one long string. This caused problems when editing an event because the combined information was loaded into additional fields. I separated date, time, location, and notes into individual database fields.

I also added more complete input validation that shows in-device popups, improved database update handling, and changed password storage so passwords are hashed instead of being stored as readable plain text strings.

These enhancements helped me move toward the course outcomes, focusing on software engineering and design as well as security. Instead of simply adding another feature to the application, I had to look at how the overall model, database, activity screens, and RecyclerView adapter worked together. The final application keeps CS 360's original purpose and appearance while improving its structure, modularity, and overall functionality.

Reflection

One of the important things I took away from these edits was how quickly a change to one part of an application can affect several other components in a cascading manner. Changing the Event model required updates to the database, event activity, adapter, and add/edit activity.

I also ran into several build errors while making these changes, including XML formatting problems and accidentally placing code in the wrong Java files since they all interact with the event manager in specific ways.

Working through those issues reinforced the OOP basics of making changes in smaller steps and testing frequently. With a bit of troubleshooting, I was able to successfully build and test the application and confirm the user-based changes worked.

Algorithms & Data Structures

Grazioso Salvare Rescue Dashboard

The artifact I used for this enhancement is the Grazioso Salvare Rescue Dashboard, originally created for CS 340 using Python, MongoDB, and Dash. I chose this project because the original rescue filtering was very basic for the original rubric.

A rescue animal either met the requirements or did not, which gave me an opportunity to improve how possible rescue animals are evaluated and chosen by the user.

Enhancement Narrative

For this enhancement, I replaced the original filtering with a weighted scoring and ranking system. I moved the rescue requirements into a more structured format and gave weights to the breeds, ages, and sexes of each animal.

Each candidate can receive up to ten points, and the results are sorted from highest to lowest score on the dashboard. The animal ID is used as a tiebreaker when scores are equal, and I added the score directly to the dashboard so the ranking is visible to the user. This demonstrates data structures, conditional logic, weighted comparisons, and sorting as mentioned in my code review.

I believe this enhancement supports Course Outcomes 3 and 4 as I originally planned. Outcome 3 is shown by redesigning the original filtering system into more of an algorithm that evaluates and ranks the animals.

I also weighed the difference between using MongoDB to narrow the candidates and Python to perform the scoring and sorting. Outcome 4 is demonstrated by applying these techniques to improve an existing application while keeping its original functionality close to that of the project from CS 340.

Enhancement Three

Databases

Grazioso Salvare Rescue Dashboard

The artifact I used for this enhancement is the Grazioso Salvare Rescue Dashboard, originally created for CS 340 using Python, MongoDB, and Dash. I chose this project again because the database was already an important part of the original application, but the searches were mostly written for specific rescue situations with narrow search criteria.

This gave me the chance to make the database more flexible and allow users to search through the shelter records based on what they are actually looking for.

Enhancement Narrative

For this enhancement, I added a dynamic database search that allows the user to search by animal type, breed, age range, and sex. The user does not have to select every option because the program builds the MongoDB query using only the information that was entered.

I also added indexes for the fields being searched to improve how MongoDB handles these queries. The search was added directly to the dashboard while keeping my previous scoring and ranking enhancement working. I also added messages for the number of results returned and when a search does not find any matching animals.

I believe this enhancement supports Course Outcome 4 as I originally planned in the outline because I used MongoDB, Python, and Dash together to improve an existing application and make the database more useful to the user.

It also gave me more experience deciding what work should be handled by the database instead of Python. MongoDB handles filtering the records based on the selected search criteria, while Python connects those results to the dashboard and handles the rest of the application. This kept the enhancement focused on the database while still working with the other parts of the project.
