Enhancement One

Software Design & Engineering

PitchEvent Android Application

PitchEvent is an Android application I originally created in CS 360. The application allows users to create an account, log in, and create and manage events in a pickup-sports-centered system that can also be adapted for other types of events.

I selected this artifact because it demonstrates my experience with Java, Android application development, SQLite database operations, and connecting multiple parts of an application into one functioning system.

Enhancement Narrative

For this enhancement, I focused on improving how events are created and edited. I added an improved event lifecycle that allows events to move through statuses such as Upcoming, Reminder Due, Completed, and Archived. The status is stored in SQLite so it remains after restarting the application or logging out.

I also improved the original event model. Previously, date and time were stored together and location and notes were stored as one long string. This caused problems when editing an event, so I separated date, time, location, and notes into individual database fields. I also added more complete input validation, improved database update handling, and changed password storage so passwords are hashed rather than stored as readable plain text.

These changes helped me work toward the course outcomes related to software engineering, design, and security. Instead of simply adding another feature, I had to consider how the event model, database, activities, and RecyclerView adapter worked together. The enhanced application keeps the original purpose and appearance of the CS 360 project while improving its structure, modularity, and functionality.

Reflection

One of the most important things I learned from this enhancement was how quickly a change to one part of an application can affect several other components. Changing the Event model required updates to the database, event activity, adapter, and add/edit activity.

I also worked through several build errors, including XML formatting issues and code being placed in the wrong Java files. Troubleshooting these problems reinforced the importance of making changes in smaller steps and testing frequently. After working through these issues, I was able to successfully build and test the application and confirm that the enhanced functionality worked as intended.
